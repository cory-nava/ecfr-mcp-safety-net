# Golden eval results, 2026-10-17: bge-small vs bge-base

Same frozen 50 queries (`eval.json`), same corpus, same code; only the embedding model differs.

- Corpus: ctrimm/ecfr-markdown @ 2dc934b (eCFR current as of 2026-10-15), 2,278 current sections indexed.
- `bge-small`: `BAAI/bge-small-en-v1.5`, 384-dim: the shipped `data/`.
- `bge-base`: `BAAI/bge-base-en-v1.5`, 768-dim: section vectors rebuilt from the same corpus for this comparison only
  (`build/build_vectors.py --model BAAI/bge-base-en-v1.5 --out <scratch>`), not shipped.
- Index: whole-section vectors (`<title>\n<body>`, front matter excluded, no instruction prefixes), brute-force cosine.

Reproduce:

```bash
python golden/eval.py --vectors data/vectors.npz --cite      # free tier as shipped
python golden/eval.py --vectors data/vectors.npz             # vectors only
python golden/eval_server.py --tier free                     # same free-tier numbers via the server's own code
```

## Reading it

- The model switch costs 2 queries at r@1 (natural 0.667 -> 0.606) and 2 at r@5. At n=50 that is within
  noise, but it points the same way in every slice where the two differ.
- bge-small was chosen for size: 127 MB vs 418 MB download, about half the RAM. Whether that is worth
  ~4pp of recall is a product call; reverting is a rebuild of `data/` with `--model BAAI/bge-base-en-v1.5`.
- The best tier (LLM rerank over chunk candidates) was not re-measured: it needs an OpenRouter key.
  Its 0.76 / 0.94 / 0.96 dates from 2026-10-13 with bge-base candidates.

## Best tier (LLM rerank) re-measured on bge-small, 2026-10-17

Same frozen 50, same code (`golden/exp_llm_rerank.py`), bge-small chunk
candidates from the shipped `data/`; `google/gemini-2.5-flash-lite`,
top-50 chunks in batches of 10, section = best chunk. Scores saved to
`golden/llm_rerank_scores_bgesmall.jsonl` (the old
`llm_rerank_scores.jsonl` is the 2026-10-13 bge-base run, kept).

| candidates | r@1 | r@3 | r@5 | cost |
|---|---|---|---|---|
| bge-base (2026-10-13) | 0.76 | 0.94 | 0.96 | $0.09 |
| bge-small (2026-10-17) | **0.76** | 0.88 | 0.90 | $0.086 |

By query type, r@1 / r@3 / r@5 (bge-small):

| type | r@1 | r@3 | r@5 |
|---|---|---|---|
| exact (n=5) | 1.000 | 1.000 | 1.000 |
| natural (n=33) | 0.788 | 0.939 | 0.970 |
| paraphrase (n=12) | 0.583 | 0.667 | 0.667 |

r@1 is identical: the reranker still puts the right section first just as
often. The gap opens at r@3/r@5 — bge-small's top-50 candidate pool misses
the gold section outright more often, so there is nothing to rerank. Same
lesson as the free tier: the candidate generator, not the reranker, is
where the 4pp went.

## Candidate variants for the reranker, 2026-10-17 (round 8)

The paid-tier re-measure showed r@1 is set by the reranker but r@3/r@5 by
the candidate pool, so three candidate variants were tested against the
query top-50 baseline. Same frozen 50, gemini-2.5-flash-lite, batches of 10,
section = best chunk. Script: `golden/exp_rerank_candidates.py`
(`--candidate-source`, `--top-n`).

| candidates | r@1 | r@3 | r@5 | cost/50q | per type r@1 (nat / para) |
|---|---|---|---|---|---|
| query top-50 (baseline) | 0.76 | 0.88 | 0.90 | $0.086 | 0.788 / 0.583 |
| hybrid: dense-50 ∪ BM25-50 | 0.70 | 0.84 | 0.88 | $0.143 | 0.758 / 0.417 |
| dense top-100 | 0.76 | 0.86 | 0.92 | $0.173 | 0.818 / 0.500 |
| **HyDE-averaged top-50** | **0.76** | **0.92** | **0.94** | $0.088 | 0.818 / 0.500 |

- **Hybrid hurts.** Worse everywhere than dense alone, and paraphrase
  collapses (0.583 → 0.417 r@1). The BM25 extras are lexical distractors
  that the LLM scorer overrates — the same surface-overlap trap that sank
  bge-reranker-base. More candidates are not better when they are
  adversarial to the scorer. Rejected.
- **Top-100 is a wash.** r@1 identical; r@3 −2pp, r@5 +2pp — noise at
  n=50 — for 2x the scoring cost. Rejected.
- **HyDE-averaged candidates + rerank is the new best: 0.76/0.92/0.94**
  at the same cost as the baseline ($0.088; HyDE passages reused from
  `golden/hyde_passages.json`, no new generation cost). Natural r@3/r@5 =
  0.970/1.000.
- Refinement of the round-7 "combo does not stack" finding: on bge-base
  candidates the combo was worse everywhere; on the weaker bge-small pool
  it gains +4pp at r@3/r@5 with r@1 unchanged. The candidate generator is
  the bottleneck, so improving candidates helps exactly where the pool is
  weakest. Adopting it as the server default would add one HyDE flash call
  per query (~$0.0001, 5–10s) — product tradeoff, not yet decided.

## Round 9 — reranker model comparison (2026-10-17)

HyDE-averaged candidates, bge-small embeddings, listwise LLM rerank. Same 50
queries; models compared on identical candidate sets.

| Reranker | r@1 | r@3 | r@5 | Cost/50 | $/query |
|---|---|---|---|---|---|
| gemini-2.5-flash-lite | 0.76 | 0.92 | 0.94 | $0.088 | $0.0018 |
| openai/gpt-6-luna | 0.875 | 1.000 | 1.000 | $0.107 | $0.0022 |
| anthropic/claude-haiku-5.5 | — | — | — | — | — |

Luna scored 48/50 (q39, q45 failed: model returned unparseable responses after
retries). On the same 48 queries flash-lite scores 0.729/0.917/0.938, so the
gap is real, not a dropout artifact: **+14.6pp r@1, perfect r@3/r@5.**

- **Luna wins big.** +15pp at r@1 and perfect recall at 3/5 for ~25% more
  cost per query ($0.0022 vs $0.0018). Luna emits ~80 reasoning tokens per
  call (chain-of-thought before scoring) — that reasoning is the quality
  edge and also the latency cost: 30–40s/batch vs flash-lite's 1–2s.
- **Haiku-5.5 unusable as reranker.** Reliable on tiny prompts (correct JSON,
  ~2s) but returns empty content / null scores / refusals on the real 15KB
  rerank prompts — 0/50 queries scored. Instruction-following breaks down at
  prompt length. Rejected.
- Scores: `golden/llm_rerank_scores_luna.jsonl` (48 queries).

## Round 10 — gpt-5.4-nano reranker (2026-10-17)

Same setup (HyDE-averaged candidates, bge-small, 50 queries). All 50 scored,
~2s/batch, $0.170 total.

| Reranker | r@1 | r@3 | r@5 |
|---|---|---|---|
| gpt-6-luna | 0.875 | 1.000 | 1.000 |
| gemini-2.5-flash-lite | 0.76 | 0.92 | 0.94 |
| **gpt-5.4-nano** | **0.58** | **0.88** | **0.94** |

- **5.4-nano loses badly.** r@1 drops 18pp vs flash-lite (0.58 vs 0.76);
  paraphrase r@1 collapses to 0.333. It is fast and reliable (50/50 scored)
  but a much worse relevance judge. Newer and pricier ($0.20/$1.25 per MTok
  vs $0.10/$0.40) does not mean better at this task. Rejected.
- Scores: `golden/llm_rerank_scores_gpt54nano.jsonl`.
